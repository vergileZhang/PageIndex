# PageIndex 实验背景

传统 RAG 通常采用“文档切块 -> 向量化 -> 向量检索 -> 拼接上下文 -> 生成回答”的流程。这种方式实现简单、通用性强，但在长文档场景中容易出现问题：固定 chunk 切分会破坏章节结构，向量检索难以利用目录、页码和层级信息，检索结果也不够可解释。对于论文、手册、报告等结构清晰的长文档，仅依赖语义相似度往往难以稳定定位到正确内容。

PageIndex 提供了一种结构化索引思路。它不是先构建向量库，而是将 PDF 解析为带页码的章节树：如果目录可用，就从目录生成结构并校准真实页码；如果目录不可用，就给正文页加入 `<physical_index_X>` 标签，让 LLM 从正文中抽取章节层级。最终得到的索引是一个 JSON Tree，包含章节标题、起止页、子节点、节点编号和摘要。

这种方式更接近人类阅读长文档的过程：先看目录判断相关章节，再进入具体页码阅读原文。因此，PageIndex 在长文档 RAG 中具有结构保留好、页码级检索清晰、结果可解释性强等优势。同时，它在建索引过程中会用 accuracy 检查章节页码是否正确，并对部分错误页码进行修正。

不过，PageIndex 也存在不足。它高度依赖 LLM 完成目录判断、结构抽取、页码校准和摘要生成，建索引成本较高；索引质量也受 PDF 文本解析效果影响。当前源码更偏研究和 demo，实现真实离线部署还需要补充本地模型适配、批量处理、多文档路由、服务化接口和错误恢复等能力。

因此，本实验选择 PageIndex 作为长文档 RAG 的结构化索引方案，重点考察其在长文档结构保留、页码级检索、可解释性以及离线部署可行性方面的表现。
